# Workshop AI Helper Prototype

Each table designs one small helper for its scenario, and Claude Code builds it. Your group makes the decisions; Claude Code does most of the coding.

## Get set up (ideally, before the workship)

We recommend using Claude Code inside VS Code rather than in the terminal: you see each change Claude makes in the editor as it happens, and can review it before accepting.

1. **Install [VS Code](https://code.visualstudio.com)** (version 1.94 or newer).
2. **Install the Claude Code extension.** In VS Code, open Extensions (`Cmd+Shift+X` on Mac, `Ctrl+Shift+X` on Windows), search for **Claude Code** by Anthropic, and click **Install**. Claude Code comes bundled with the extension; there's nothing else to install for it.
3. **Install the tools your prototype needs:**
   - **[Node.js](https://nodejs.org) 22 or newer**, to run the prototype and the example. Download the **LTS** version from [nodejs.org/en/download](https://nodejs.org/en/download) and run the installer with the default options (it also installs `npm`). Or run `brew install node` on Mac or `winget install OpenJS.NodeJS.LTS` on Windows. Then restart VS Code so its terminal can find `node`. If you already had Node, check that it's version 22 or newer; if not, install the current LTS over it.
   - **Git**, to get your table's repo. On Mac, running `git --version` offers to install it. On Windows, install [Git for Windows](https://git-scm.com/downloads/win); Claude Code also uses it to run commands.
   - **jq**, which the session log uses. It comes with recent versions of macOS. Otherwise, run `brew install jq` on Mac or `winget install jqlang.jq` on Windows.

   Check everything is ready by running these in VS Code's terminal (**Terminal → New Terminal**). Each should print a version number:

   ```sh
   node --version
   git --version
   jq --version
   ```
4. **Open your table's repo.** Clone it with **Source Control → Clone Repository** (or `git clone <your repo URL>`), then **File → Open Folder** and choose the folder.
5. **Start Claude Code.** Open any file, then click the Claude Code spark icon at the top right of the editor (or **✻ Claude Code** in the bottom-right status bar). Sign in with a paid Claude account (Pro, Max, Team or Enterprise) or a Claude Console account; the free plan doesn't include Claude Code. If Claude Code asks whether to trust this project's settings, say yes: that turns on the session log.

## What's in this repo

| Path | What it's for |
| :--- | :--- |
| `agent-spec.yaml` | Your table's working spec. Paste the contents of the agent card into it; the comments show which card field goes where. |
| `example/` | A finished example helper to look at before you start. See [Worked example](#worked-example) below. |
| `templates/build-note.md` | Template Claude Code uses to write your table's `build-note.md`. Do not edit this file. |
| `CLAUDE.md` | Build and safety rules Claude Code follows automatically.  Do not edit this file. |
| `.env.example` | Copy to `.env` and add your table's Gemini API key. Only needed for voice or image features. |
| `.claude/settings.json` | Logs every prompt and file change to `logs/claude-session-log.jsonl`.  Do not edit this file.|
| `.github/copilot-instructions.md` | Points other coding assistants to the same rules.  Do not edit this file.|

## Steps

1. **Fill in the spec.** Paste the contents of the chosen agent card into `agent-spec.yaml`. Claude Code can help. Use made-up personal details only, and only learner-profile lines marked "Yes".
2. **Add your Gemini key** if your helper needs voice to text, text to voice, or images. Copy `.env.example` to a new file named `.env` and paste the key after `GEMINI_API_KEY=`. Do this yourself in the editor; never paste the key into Claude Code.
3. **Paste the prompt below** into Claude Code, opened in your table's own repo you gained access to before the workshop. 
4. **Check Claude's plan** before it builds. Correct anything wrong, then tell it to go ahead.
5. **Try it.** The adult reviewer checks and releases the draft first. Then the learner tries it. Revise based on what they say.
6. **Review Claude Code's `build-note.md`** together. Share it only if the whole group agrees.
7. **Record your final version.** Make a short screen recording of the prototype working: the adult review, the release, and what the learner sees. Upload it to the [workshop Google Drive folder](https://drive.google.com/drive/folders/1bnWKoQ6GrXeLp45f0ZiXgrWYLaPN-eYv?usp=sharing), named with your table alias and helper name (e.g., "Table 1: Field Trip Accessibility Helper"). Record the screen only, and make sure no real names or learner details are visible.

## Worked example

`example/` shows what a finished prototype can look like. It was built with Claude Code from a filled-in spec, [example/agent-spec.yaml](example/agent-spec.yaml), based on the made-up scenario of Malia, age 9, whose class is going on a pond study field trip.

**What it does:** the teacher pastes or uploads the trip agenda. The helper checks it against made-up profiles for several students and flags anything that may be a barrier, such as steps on the path, a bus that may not have a lift, or a noisy talk. For each flag it proposes a change for the whole class, so no student is left waiting while the others go ahead. The teacher accepts, edits or rejects each change and approves the revised agenda. Then they can show the student a picture-card preview of the day.

**To run it** (needs [Node.js](https://nodejs.org) 22 or newer):

```sh
cd example
npm install
npm run dev
```

Open the address it prints (usually http://localhost:5173), press **Load example agenda**, then **Check agenda**. 

**Can't run it?** Watch the [screen recording of the example](https://drive.google.com/file/d/1kL2nd_9bVnNbWo_R8Pz0Kzdb5OtvKJpU/view?usp=drive_link) instead.

## Paste-ready prompt

```text
Read agent-spec.yaml, CLAUDE.md, and templates/build-note.md before coding. First, summarize in plain language: who the helper is for and when it is used; its single job; allowed and prohibited inputs; the learner-profile details it may use; its output and who receives it; the educator/parent reviewer required before the learner sees anything; accessibility needs; and every "must never" rule. Point out anything missing or conflicting and ask only questions that block a safe, useful prototype. Do not start building until I confirm your summary.

After I confirm, build the smallest working local prototype for this helper. Do not add a login, saved data, message sending, or other external side effect. If an accessibility need calls for voice to text, text to voice, or images, follow the Gemini section of CLAUDE.md. The output must be an editable draft shown first in a separate educator/parent review screen; the learner view shows it only after an explicit release, and approval clears if the draft or its inputs change. Implement the stated accessibility needs, but don't claim they work until the learner has tried them.

Add focused tests for the expected case, missing or uncertain information, and at least one "must never" rule, including that the learner can't see output before adult review. Run the tests. Keep build-note.md up to date from the template, using logs/claude-session-log.jsonl for prompts and changed files: summarize, don't copy the chat, and include no names or identifying details. Leave the sharing decision as "Not decided". When done, tell us which files changed, how to run the prototype, the test results, your assumptions, and what still needs testing with the learner. Do most of the coding yourself; pause for our decisions about learner needs, content, and boundaries.
```

## Good to know

- **Your prompts are logged word for word** in `logs/claude-session-log.jsonl`, and the log is committed to the repo. Don't type real names, records, grades, or passwords.
